# راهنمای فرانت: کپی تصاویر شماره پیگیری به شناسه قبض

این API تصاویر درخواست را از فولدر شماره پیگیری به فولدر شناسه قبض کپی می‌کند. فایل‌های مبدأ باقی می‌مانند. بک‌اند ابتدا بررسی می‌کند که دو شناسه به هم مرتبط باشند و کاربر به منطقه درخواست دسترسی داشته باشد.

## ۱. ارسال درخواست

```http
POST /v1/open-km/copy-track-images-to-bill
Authorization: Bearer <access-token>
Content-Type: application/json
```

بدنه درخواست:

```json
{
  "trackNumber": 123456,
  "billId": "1234567890123"
}
```

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `trackNumber` | عدد صحیح | اجباری؛ بزرگ‌تر از صفر و حداکثر `2147483647`. |
| `billId` | رشته | اجباری؛ فقط رقم‌های انگلیسی. آن را به عدد تبدیل نکنید تا صفرهای ابتدای آن حفظ شود. |

اگر ورودی فرم رقم فارسی یا عربی دارد، پیش از ارسال آن را به رقم انگلیسی تبدیل کنید. نیازی به ارسال فایل، مسیر فولدر یا UUID نیست. فولدر مقصد در صورت نیاز توسط بک‌اند ساخته می‌شود.

## ۲. پاسخ را چطور بخوانیم؟

نکته اصلی: **HTTP 200 و `success: true` به‌تنهایی به معنی کپی موفق همه تصاویر نیستند. حتماً `data.isComplete` را بررسی کنید.**

نمونه پاسخ با فیلدهای موردنیاز فرانت:

```json
{
  "success": true,
  "httpStatusCode": 200,
  "successMessage": "کپی تصاویر تکمیل شد",
  "data": {
    "trackNumber": 123456,
    "billId": "1234567890123",
    "isLinked": true,
    "isComplete": true,
    "copiedCount": 1,
    "skippedCount": 0,
    "conflictCount": 0,
    "failedCount": 0,
    "files": [
      {
        "sourceUuid": "source-document-uuid",
        "fileName": "photo.jpg",
        "destinationUuid": "destination-document-uuid",
        "status": "Copied",
        "errorCode": null,
        "message": null
      }
    ],
    "warnings": []
  }
}
```

| فیلد داخل `data` | کاربرد در فرانت |
| --- | --- |
| `isComplete` | اگر `true` باشد، تمام تصاویر کپی شده‌اند یا از قبل به همان شکل در مقصد بوده‌اند. |
| `copiedCount` | تعداد تصاویر تازه کپی‌شده. |
| `skippedCount` | تعداد تصاویر تکراری که دوباره بارگذاری نشده‌اند. |
| `conflictCount` | تعداد فایل‌های دارای تعارض نام و محتوا. |
| `failedCount` | تعداد فایل‌هایی که پردازش آن‌ها خطا داشته است. |
| `files` | جزئیات نتیجه هر تصویر؛ برای نمایش جدول نتیجه. |
| `warnings` | هشدارهای عملیات؛ حتی در صورت `isComplete: true` بررسی شود. |

اگر دو شناسه مرتبط نباشند، درخواست با خطا برمی‌گردد؛ منتظر پاسخ موفق با `isLinked: false` نباشید.

## ۳. اگر فایلی از قبل در مقصد باشد

مقدار `status` دقیقاً با همین حروف انگلیسی برمی‌گردد:

| `status` | چه اتفاقی افتاده؟ | عنوان پیشنهادی برای کاربر |
| --- | --- | --- |
| `Copied` | تصویر و اطلاعات آن کپی شده‌اند. | کپی شد |
| `Skipped` | نام و محتوای فایل یکسان بوده؛ بارگذاری دوباره انجام نشده و متادیتای مقصد از مبدأ به‌روزرسانی شده است. | از قبل موجود است |
| `Conflict` | نام یکسان ولی محتوا متفاوت است؛ فایل مقصد بازنویسی نشده است. | تعارض فایل |
| `Failed` | خواندن، بارگذاری یا ثبت متادیتا خطا داشته است؛ توضیح در `message` قرار دارد. | ناموفق |

اگر محتوا یکسان ولی نام فایل متفاوت باشد، فایل جدید کپی می‌شود. وجود تعارض یا خطا مانع پردازش بقیه تصاویر نمی‌شود.

در جدول نتیجه، نمایش «نام فایل»، «وضعیت» و «توضیح» کافی است. برای منطق برنامه از `status` و `errorCode` استفاده کنید؛ متن فارسی `message` را شرط برنامه قرار ندهید.

## ۴. نمایش نتیجه به کاربر

| حالت | رفتار پیشنهادی |
| --- | --- |
| `isComplete: true` و بدون هشدار | پیام موفقیت و تعداد فایل‌های کپی‌شده و تکراری نمایش داده شود. |
| `isComplete: false` | پیام «بعضی تصاویر کپی نشدند» همراه جدول نتیجه نمایش داده شود. |
| `files` خالی است | پیام «تصویری برای کپی وجود نداشت» نمایش داده شود. |
| `data.warnings` خالی نیست | هشدارها در کنار نتیجه فایل‌ها نمایش داده شوند. |

پس از دریافت نتیجه، فهرست تصاویر مقصد را دوباره دریافت کنید؛ حتی اگر نتیجه ناقص باشد، ممکن است بخشی از تصاویر کپی شده باشند.

### هشدار ثبت گزارش عملیات

اگر کپی انجام شود ولی ثبت گزارش پایانی خطا بدهد، نتیجه فایل‌ها همچنان برمی‌گردد:

```json
{
  "code": "CompletionAuditFailed",
  "message": "ثبت گزارش پایانی عملیات انجام نشد؛ نتیجه کپی فایل‌ها در پاسخ موجود است"
}
```

این مورد در آرایه **`data.warnings`** قرار دارد؛ آن را با `warnings` سطح اصلی پاسخ اشتباه نگیرید. به‌خاطر این هشدار، کپی موفق را ناموفق نمایش ندهید و درخواست را خودکار تکرار نکنید.

## ۵. خطا و تلاش مجدد

| حالت | رفتار پیشنهادی |
| --- | --- |
| HTTP 400 | معمولاً ورودی نامعتبر، نبود ارتباط دو شناسه، نداشتن دسترسی منطقه یا نبود فولدر مبدأ است. پیام `errors[].message` نمایش داده شود. |
| HTTP 401 یا 403 | روال فعلی پروژه برای ورود یا دسترسی اجرا شود. |
| HTTP 500 یا خطای شبکه | پیام مناسب نمایش داده شود و امکان تلاش مجدد در اختیار کاربر باشد. ممکن است بخشی از عملیات قبلاً انجام شده باشد. |

برای فایل‌های `Failed`، مقدار `errorCode` یکی از موارد زیر است:

| `errorCode` | معنی |
| --- | --- |
| `ReadSource` | خواندن یا بررسی اطلاعات تصویر انجام نشده است. |
| `Upload` | بارگذاری کامل نشده یا پاسخ آن دریافت نشده است. |
| `Metadata` | فایل در مقصد موجود است، اما ثبت اطلاعات آن تکمیل نشده است. |

تلاش مجدد با **همان `trackNumber` و `billId`** انجام می‌شود. بک‌اند فایل‌های موجود را دوباره بررسی می‌کند؛ فایل یکسان دوباره بارگذاری نمی‌شود و متادیتای ناقص قابل تکمیل است. تعارض `Conflict` با تکرار درخواست خودبه‌خود برطرف نمی‌شود.

تا زمان دریافت پاسخ، دکمه کپی را غیرفعال و حالت انتظار نمایش دهید. قطع درخواست از سمت مرورگر به معنی برگرداندن فایل‌های کپی‌شده نیست.

## ۶. نمونه فراخوانی با JavaScript

در صورت وجود کلاینت مشترک API در پروژه، همین درخواست را با آن ارسال کنید. نمونه زیر با `fetch` است و فرض می‌کند ورودی‌ها پیش‌تر اعتبارسنجی شده‌اند:

```javascript
async function copyTrackImagesToBill({ baseUrl, token, trackNumber, billId }) {
  const response = await fetch(
    `${baseUrl.replace(/\/$/, "")}/v1/open-km/copy-track-images-to-bill`,
    {
      method: "POST",
      headers: {
        Authorization: `Bearer ${token}`,
        "Content-Type": "application/json"
      },
      body: JSON.stringify({ trackNumber, billId })
    }
  );

  const body = await response.json().catch(() => null);

  if (!response.ok || body?.success !== true || !body?.data) {
    const message = body?.errors?.map(error => error.message).join("\n");
    throw new Error(message || "دریافت نتیجه کپی تصاویر انجام نشد");
  }

  return {
    message: body.successMessage,
    result: body.data
  };
}
```

خروجی `result.isComplete` وضعیت کپی را مشخص می‌کند. خطای یک فایل در پاسخ HTTP 200، باعث `throw` در این تابع نمی‌شود؛ جدول نتیجه و هشدارها باید توسط صفحه نمایش داده شوند.
