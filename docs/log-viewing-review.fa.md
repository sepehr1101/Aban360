# بازبینی مشاهدهٔ لاگ‌ها

تاریخ: ۱۴۰۵/۰۸/۱۱ (۲۰۲۶/۱۱/۰۲)

## اصلاحات

- مشاهدهٔ لاگ سیستم (`/v1/logging/get`): تبدیل مستقیم ساعت با `DateTime.ParseExact` می‌توانست برای ساعت نامعتبر یا ارقام فارسی، `FormatException` و پاسخ ۵۰۰ ایجاد کند. تبدیل تاریخ و ساعت اکنون با اعتبارسنجی مشترک انجام می‌شود؛ ورودی نامعتبر خطای برنامه و پاسخ ۴۰۰ می‌دهد. ارقام فارسی، عربی و انگلیسی پذیرفته می‌شوند. قالب تاریخ `yyyy/MM/dd` و ساعت `HH:mm` است.
- بازهٔ معکوس و سطح لاگ نامعتبر قبل از فراخوانی دیتابیس رد می‌شوند. بازهٔ برابر، مطابق رفتار قبلی مشاهدهٔ لاگ، مجاز است.
- وقتی سطح لاگ ارسال نشود، مقدار پیش‌فرض `None` است و همهٔ سطح‌ها نمایش داده می‌شوند. قبلاً مقدار صفرِ تعریف‌نشده باعث جست‌وجوی سطح `0` و نتیجهٔ خالی می‌شد.
- در فیلتر دیتابیس، `Trace` به `Verbose` و `Critical` به `Fatal` نگاشت شده‌اند تا با نام سطح‌های Serilog مطابقت داشته باشند.
- مشاهدهٔ لاگ عملیات (`/v1/op-log/get`): تبدیل تاریخ نامعتبر می‌توانست خطای تبدیل مدیریت‌نشده بدهد. اکنون ورودی و ترتیب تاریخ‌ها بررسی می‌شوند. اتصال خواندن دیتابیس پس از اتمام آزاد می‌شود.
- هندلرهای خواندن فایل لاگ ارزیابی و کنتور، یک `FileStream` اضافی و بدون بستن ایجاد می‌کردند. این جریان اضافی حذف شد. کنترلرهای فعلی دانلود فایل مستقیماً فایل را برمی‌گردانند؛ اصلاح مذکور مربوط به هندلرهای خواندن محتوای متنی است.

## بررسی‌های انجام‌شده

- پروژهٔ `Aban360.LogViewing.SmokeTests`: تعداد ۵۸ بررسی موفق؛ تبدیل تاریخ و ارقام محلی، پیش‌فرض سطح، ورودی‌های نامعتبر، کد ۴۰۰ و متن توضیح خطا، عدم ارسال ورودی نامعتبر به کوئری، انتقال cancellation، اعتبارسنجی لاگ عملیات و آزاد شدن فایل پس از خواندن.
- تست HTTP از هندلر واقعی مشاهدهٔ لاگ و `GlobalExceptionHandler` واقعی، در یک مسیر آزمایشی استفاده می‌کند و پاسخ ۴۰۰ برای ورودی نامعتبر را بررسی می‌کند. این تست، تست کامل کنترلر و احراز هویت محیط اجرا نیست.
- تست‌های موجود `Aban360.HttpReports.SmokeTests` موفق بودند.
- ساخت پروژهٔ تست جدید و `Aban360.SystemPool.Persistence` بدون خطای کامپایل موفق بود. هشدارهای پروژه در خروجی ساخت وجود دارند.

دستورهای تکرار بررسی:

```powershell
dotnet run --project tests/Aban360.LogViewing.SmokeTests
dotnet run --project tests/Aban360.HttpReports.SmokeTests
dotnet build Aban360.SystemPool.Persistence
```

## حدود نتیجه

اعتبارسنجی مشاهدهٔ لاگ سیستم و لاگ عملیات از `InvalidDateException` و `CustomValidationException` استفاده می‌کند که از `BaseException` ارث می‌برند. متن خطا نام فیلد شروع یا پایان، قالب مورد انتظار یا علت نامعتبر بودن بازه را مشخص می‌کند. برای سطح نامعتبر از جمله صفر، مقادیر مجاز ۱ تا ۷ و روش درخواست همهٔ سطح‌ها توضیح داده می‌شود. تست HTTP مقدار `errors[0].code` و متن `errors[0].message` را نیز بررسی می‌کند.

در این بررسی، اتصال به دیتابیس واقعی، اجرای کوئری‌های SQL روی داده‌های واقعی، مشاهدهٔ رابط کاربری و استقرار انجام نشده است. بنابراین علت دقیق خطای گزارش‌شدهٔ کاربر هنوز قطعی نیست؛ اصلاحات بالا ایرادهای مشخص کد هستند.

کوئری‌های لاگ سیستم و گزارش HTTP همچنان جدول `[Aban360].dbo.Logs` و قالب XML موجود Properties را فرض می‌کنند. خطای اتصال، دسترسی دیتابیس، نبود جدول، تفاوت قالب ذخیره‌سازی یا timeout باید با خطای واقعی محیط بررسی شود. تنظیمات و کنترلر گزارش HTTP که از قبل تغییر داشتند در این کار ویرایش نشدند.
