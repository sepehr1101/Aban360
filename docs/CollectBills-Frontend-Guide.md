# راهنمای مختصر CollectBills برای فرانت

مسیر پایه: `/v1/collect-bills` — همه درخواست‌ها نیازمند توکن Bearer هستند.
تاریخ‌ها شمسی و با قالب `yyyy/MM/dd` هستند.

| مسیر | روش پیشنهادی | ورودی | کاربرد و پاسخ موفق |
| --- | --- | --- | --- |
| `file-create` | POST | بدنه: `{"dateJalali":"1405/08/23"}` | ساخت فایل داده‌های همان روز و دانلود مستقیم ZIP در همان پاسخ؛ عملیات ارسال انجام نمی‌دهد. |
| `get` | GET یا POST | GET: پارامترهای Query؛ POST: بدنه `{"fromDateJalali":"1405/08/01","toDateJalali":"1405/08/23"}` | گزارش JSON وضعیت پردازش و ارسال، آخرین مرحله، توضیحات و `fileName`؛ فایل دانلود نمی‌کند. |
| `download/{fileName}` | GET یا POST | نام کامل فایل ZIP در مسیر | دانلود فایل موجود؛ `fileName` را می‌توان از گزارش گرفت. فایل ناموجود خطا می‌دهد. |
| `send-file` | POST | ندارد | ثبت پردازش و ارسال اطلاعات دیروز در صف پس‌زمینه؛ پاسخ `200` بدون بدنه. وضعیت نهایی را با `get` پیگیری کنید. |
| `send-file/{day}` | GET یا POST — منسوخ | عدد فاصله از امروز؛ مثلاً `-1` یعنی دیروز | در توسعه جدید استفاده نشود؛ همچنان برای سازگاری فعال است. پاسخ `200` بدون بدنه فقط ثبت کار در صف است. |

نکات:

- پاسخ موفق `file-create` و `download` فایل با نوع `application/zip` است؛ در Axios از `responseType: 'blob'` استفاده کنید. این پاسخ‌ها پوشش JSON سایر APIها را ندارند و interceptor نباید `data.data` را استخراج کند.
- نام فایل دانلود از هدر `Content-Disposition` قابل دریافت است؛ خطاها به‌صورت JSON برمی‌گردند و در حالت blob باید جداگانه خوانده شوند.
- برای `file-create` از POST استفاده کنید؛ هرچند GET هم ثبت شده، ورودی فعلی آن از بدنه خوانده می‌شود.
- `send-file` معادل GET هم دارد؛ برای شروع عملیات از POST استفاده کنید. موفقیت این درخواست به معنی اتمام پردازش یا ارسال نیست.
- برای ارسال دیروز از `send-file` و برای دانلود داده‌های تاریخ دلخواه از `file-create` استفاده کنید؛ این دو عملیات متفاوت‌اند.
