# مأموریت فرانت برای نمایش جزئیات خطای HTTP

## مسئله و هدف

در صفحهٔ خطاهای HTTP، ادمین می‌تواند خطاهای چند ساعت اخیر را ببیند و یک ردیف را پیدا کند. فهرست خلاصهٔ درخواست را نشان می‌دهد. برای عیب‌یابی یک خطای خاص، مثلاً پاسخ ۵۰۰، ادمین باید بتواند روی «مشاهده جزئیات» همان ردیف بزند و اطلاعات کامل‌تر، از جمله exception و stack trace ثبت‌شده، را ببیند.

این قابلیت را به جدول موجود اضافه کنید. جزئیات فقط بعد از انتخاب یک ردیف بارگیری شود تا بارگذاری اولیه، فیلترها و صفحه‌بندی جدول مستقل از آن بمانند. [راهنمای فهرست خطاهای HTTP](http-error-logs-frontend.fa.md)

## قرارداد API جزئیات

```http
GET /v1/logging/errors/12345
Authorization: Bearer <access_token>
Accept: application/json
```

- به‌جای `12345`، مقدار `id` همان ردیف را بفرستید. درخواست body، فیلتر تاریخ یا `traceId` نمی‌گیرد.
- از Base URL و کلاینت احراز هویت فعلی فرانت استفاده کنید. سرور دسترسی را با نقش ادمین کنترل می‌کند.
- در پاسخ HTTP 200، جزئیات در `data` یک **شیء JSON** است. نمونهٔ زیر شکل `data` را نشان می‌دهد.

```json
{
  "id": 12345,
  "dateJalali": "1405/08/13",
  "time": "12:29:15",
  "timeStamp": "2026-11-04T12:29:15.523",
  "statusCode": 500,
  "level": "Error",
  "requestMethod": "GET",
  "routeTemplate": "v1/example/{id}",
  "traceId": "example-trace-id",
  "userId": null,
  "elapsedMilliseconds": 182.5,
  "message": "HTTP GET v1/example/{id} completed 500 in 182.5 ms",
  "exception": "System.InvalidOperationException: Example failure\n   at ExampleService.Run()"
}
```

`requestMethod`، `routeTemplate`، `traceId`، `userId`، `level`، `elapsedMilliseconds`، `message` و `exception` می‌توانند `null` باشند. زمان نمایشی را از `dateJalali` و `time` بگیرید. `routeTemplate` قالب مسیر است و ممکن است مقدار `<unmatched>` داشته باشد. اطلاعات Serilog به شکل فیلدهای JSON برمی‌گردند و نیازی به پردازش XML در فرانت نیست.

`exception` متن exception و stack trace ذخیره‌شده در همان ردیف است. برای ردیف‌های قدیمی یا پاسخ ۵۰۰ بدون exception ثبت‌شده، مقدار آن می‌تواند `null` باشد. در این حالت پیام «جزئیات فنی برای این خطا ثبت نشده است» را نمایش دهید.

## رفتار صفحه

1. برای هر ردیف `4xx` یا `5xx` عمل «مشاهده جزئیات» را اضافه کنید و از پنل یا دیالوگ موجود پروژه استفاده کنید.
2. پس از انتخاب، وضعیت بارگذاری جزئیات را در همان پنل نشان دهید. اگر کاربر ردیف دیگری انتخاب کرد یا پنل را بست، درخواست قبلی را لغو کنید یا پاسخ دیررس آن را کنار بگذارید.
3. کد پاسخ، تاریخ و ساعت، متد، مسیر، مدت اجرا و شناسهٔ پیگیری را نمایش دهید. متن لاگ و exception را به‌صورت متن ساده و با حفظ خط‌های جدید نمایش دهید. برای stack trace و شناسه‌ها از جهت چپ‌به‌راست استفاده کنید.
4. وضعیت HTTP فراخوانی جزئیات را از `data.statusCode` جدا کنید. برای نمونه، پاسخ موفق API می‌تواند HTTP 200 باشد و در دادهٔ خود یک خطای ۵۰۰ تاریخی داشته باشد.
5. برای HTTP 404 خود API پیام «این لاگ دیگر در دسترس نیست» را نمایش دهید. برای HTTP 401 یا 403 از رفتار احراز هویت موجود استفاده کنید. برای خطای شبکه یا سرور، پیام خطا و امکان تلاش دوباره در پنل جزئیات بگذارید. پردازش این وضعیت‌ها را به وجود بدنهٔ JSON وابسته نکنید.

## معیار تحویل

- بارگذاری فهرست هیچ فراخوانی جزئیاتی ایجاد نمی‌کند. کلیک روی یک ردیف، جزئیات همان `id` را می‌گیرد و فیلترها و شمارهٔ صفحه حفظ می‌شوند.
- یک ردیف ۵۰۰ با exception و یک ردیف بدون exception هر دو قابل مشاهده‌اند.
- یک ردیف ۴۰۴ تاریخی در پاسخ موفق باز می‌شود. پاسخ HTTP 404 خود API حالت «لاگ در دسترس نیست» را نشان می‌دهد.
- اگر کاربر سریع دو ردیف متفاوت را باز کند، پاسخ ردیف قبلی جای جزئیات ردیف انتخاب‌شده را نمی‌گیرد.
