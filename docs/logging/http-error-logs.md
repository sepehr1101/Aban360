# مشاهده خطاهای HTTP

راهنمای اتصال و پیاده‌سازی صفحه برای برنامه‌نویس فرانت: [مستندات فرانت](http-error-logs-frontend.fa.md).

`GET /v1/logging/errors`

نیازمند ورود و عضویت در نقش تنظیم‌شده در `ApiSettings:AdminRoleName`، مانند سایر گزارش‌های HTTP است.

نمونه درخواست:

```http
GET /v1/logging/errors?statusCodeClass=4XX&fromDate=1405%2F08%2F01&toDate=1405%2F08%2F12&fromTime=08%3A00&toTime=18%3A30&page=1&pageSize=50
```

| پارامتر | توضیح |
| --- | --- |
| `statusCodeClass` | الزامی؛ `4XX` برای کدهای 400 تا 499 یا `5XX` برای کدهای 500 تا 599؛ حروف کوچک هم پذیرفته می‌شود. |
| `fromDate`, `toDate` | الزامی؛ تاریخ شمسی با قالب `yyyy/MM/dd`؛ ارقام فارسی و عربی هم پذیرفته می‌شوند. |
| `fromTime`, `toTime` | الزامی؛ ساعت ۲۴ ساعته با قالب `HH:mm`. |
| `page` | شماره صفحه از ۱؛ پیش‌فرض ۱. |
| `pageSize` | تعداد ردیف از ۱ تا ۲۰۰؛ پیش‌فرض ۵۰. |

بازه پیوسته از تاریخ و ساعت شروع تا انتهای دقیقه تاریخ و ساعت پایان است؛ فیلتر ساعت جداگانه برای تک‌تک روزها اعمال نمی‌شود. مثلاً از ۱ آبان ساعت ۰۸:۰۰ تا ۲ آبان ساعت ۱۸:۳۰، ساعات شب بین این دو تاریخ نیز در بازه قرار می‌گیرد. حداکثر فاصله شروع و پایان ۳۱ روز است. ورودی نامعتبر پاسخ 400 می‌دهد.

`data` در پاسخ استاندارد پروژه آرایه‌ای از ردیف‌های زیر است؛ جدیدترین خطا ابتدا برمی‌گردد و برای زمان برابر، شناسه بزرگ‌تر اول است. هر ردیف یک درخواست است؛ کدهایی مثل 400 و 401 به‌صورت مستقل نمایش داده می‌شوند و تجمیع نمی‌شوند. صفحه بدون نتیجه آرایه خالی برمی‌گرداند.

```json
{
  "id": 12345,
  "dateJalali": "1405/08/12",
  "time": "10:24:35",
  "statusCode": 401,
  "requestMethod": "GET",
  "routeTemplate": "v1/example/{id}",
  "traceId": "example-trace-id",
  "userId": null,
  "message": "HTTP GET v1/example/{id} completed 401 in 2 ms; TraceId example-trace-id; UserId null"
}
```

داده‌ها از رویدادهای ثبت‌شده توسط `HttpRequestLoggingMiddleware` در `[Aban360].dbo.Logs` خوانده می‌شوند. فیلتر بر مبنای `StatusCode` داخل properties ساختاریافته XML است، نه سطح لاگ؛ در نتیجه 4XXهای ثبت‌شده با سطح Information نیز برمی‌گردند. رویدادهایی که کد وضعیت ساختاریافته ندارند، خطاهای ثبت‌نشده و درخواست‌هایی که به سرور نرسیده‌اند در این گزارش وجود ندارند. تاریخ و ساعت با همان مبنای زمانی ذخیره‌شده در لاگ تفسیر می‌شوند، مطابق گزارش‌های فعلی پروژه.

آزمون اعتبارسنجی و تبدیل بازه، بدون اتصال به پایگاه داده:

```powershell
dotnet run --project tests/Aban360.HttpErrorLogs.SmokeTests
```
