# راهنمای تصاویر قرائت برای اپلیکیشن اندروید

این راهنما شامل ارسال عکس قرائت، دریافت فهرست تصاویر یک قبض و دریافت تصویر برای نمایش است. `{apiBaseUrl}` آدرس پایه API است.

## ۱. ارسال تصویر

```http
POST {apiBaseUrl}/v1/open-km/add-reading-image
Authorization: Bearer {accessToken}
Content-Type: multipart/form-data; boundary=...
```

هر درخواست فقط یک تصویر می‌پذیرد. بدنه باید فرم چندبخشی باشد، نه JSON یا Base64:

| نام بخش فرم | محتوا | الزامی |
| --- | --- | --- |
| `billId` | شناسه قبض به‌صورت متن با ارقام انگلیسی | بله |
| `file` | بایت‌های فایل تصویر با نام فایل و نوع `image/jpeg` یا `image/png` | بله |

در اندروید، محتوای تصویر انتخاب‌شده از دوربین یا گالری را در بخش `file` ارسال کنید؛ ارسال مسیر فایل یا رشته `content://...` به‌تنهایی کافی نیست. ساخت `boundary` و هدر کامل `Content-Type` را به ابزار شبکه اپلیکیشن بسپارید.

نام کاربر، تاریخ، نام نهایی فایل و واترمارک را ارسال نکنید؛ این اطلاعات توسط سرور تعیین می‌شوند. هویت آپلودکننده از توکن ورود گرفته می‌شود.

### شرایط پذیرش تصویر

- فرمت واقعی فایل باید JPEG یا PNG باشد؛ تغییر پسوند فایل کافی نیست.
- حجم فایل باید بیشتر از صفر و حداکثر ۲۰ مگابایت (۲۰٬۹۷۱٬۵۲۰ بایت) باشد.
- عرض حداقل ۱۶۰ پیکسل، ارتفاع حداقل ۱۲۰ پیکسل و حاصل‌ضرب عرض و ارتفاع حداکثر ۲۵٬۰۰۰٬۰۰۰ پیکسل باشد.
- شناسه قبض باید معتبر و مربوط به مشترک موجود باشد و کاربر به منطقه مشترک دسترسی داشته باشد.

اگر خروجی دوربین فرمت دیگری دارد، پیش از ارسال به JPEG یا PNG تبدیل شود. در صورت نیاز، حجم و ابعاد تصویر در اپلیکیشن کاهش داده شود تا محدودیت‌های بالا رعایت شوند.

### نتیجه ارسال

در پاسخ موفق:

| فیلد پاسخ | کاربرد در اپلیکیشن |
| --- | --- |
| `success` | نشان‌دهنده موفقیت عملیات |
| `data.uuid` | شناسه تصویر ذخیره‌شده؛ برای دریافت تصویر نگه دارید |
| `data.size` | اندازه فایل ذخیره‌شده |

پس از موفقیت، پیام «تصویر با موفقیت ارسال شد» نمایش دهید و در صورت نمایش گالری، فهرست تصاویر را دوباره دریافت کنید.

تصویر ذخیره‌شده JPEG است و پایین آن تاریخ شمسی و ساعت بارگذاری، شناسه قبض و نام کاربر درج می‌شود. تاریخ درج‌شده زمان بارگذاری روی سرور است، نه زمان عکاسی. جهت عکس موبایل در صورت وجود اطلاعات جهت تصویر اصلاح می‌شود؛ درج واترمارک در اپلیکیشن لازم نیست.

هنگام ارسال، دکمه ارسال را غیرفعال کنید تا یک تصویر با چند بار لمس دوباره فرستاده نشود. هر ارسال موفق یک تصویر جدید ایجاد می‌کند. اگر ارتباط قطع شد یا زمان انتظار تمام شد، پیش از ارسال مجدد فهرست تصاویر را بررسی کنید؛ ممکن است تصویر قبلاً ذخیره شده باشد.

## ۲. دریافت فهرست تصاویر قرائت

```http
GET {apiBaseUrl}/v1/open-km/reading-directory-tree2?billId={billId}
Authorization: Bearer {accessToken}
```

این مسیر فقط تصاویر قرائت همان قبض را برمی‌گرداند. شناسه قبض و دسترسی کاربر در این درخواست نیز بررسی می‌شوند.

فهرست در `data.document` قرار دارد. فیلدهای کاربردی هر عضو:

| فیلد | کاربرد |
| --- | --- |
| `uuid` | شناسه لازم برای دریافت تصویر |
| `fileTitle` | عنوان نمایشی؛ «تصویر قرائت کنتور» |
| `mimeType` | نوع محتوای تصویر |
| `created` | تاریخ ثبت سند |
| `actualVersion.size` | اندازه فایل |

اگر `data.document` آرایه خالی بود، وضعیت «تصویری برای این قبض ثبت نشده است» نمایش دهید. سایر مشخصات سند ممکن است در پاسخ وجود داشته باشند؛ برای نمایش تصویر از `uuid` استفاده کنید و به مسیر یا قالب نام فایل وابسته نشوید.

## ۳. دریافت محتوای هر تصویر

با `uuid` به‌دست‌آمده از پاسخ آپلود یا فهرست، مسیر موجود دریافت تصویر را فراخوانی کنید:

```http
GET {apiBaseUrl}/v1/open-km/document-binary?documentId={uuid}&isThumbnail=false
```

برای نمایش نسخه اصلی، `isThumbnail=false` ارسال شود. دریافت محتوا و تبدیل آن برای نمایش، مطابق قرارداد فعلی همین مسیر در اپلیکیشن انجام شود. پاسخ فهرست تصاویر شامل خود محتوای عکس‌ها نیست و برای هر تصویر موردنیاز، درخواست دریافت محتوا جداگانه لازم است.

## ۴. مدیریت خطا در اپلیکیشن

- تنها پس از دریافت پاسخ موفق، تصویر را ارسال‌شده علامت بزنید.
- در خطاهای اعتبارسنجی، پیام برگشتی API را از `errors[].message` نمایش دهید؛ مانند شناسه قبض نامعتبر، تصویر نامعتبر یا حجم بیش از حد مجاز.
- در پایان اعتبار ورود، مطابق روال ورود فعلی اپلیکیشن عمل کنید.
- برای خطای شبکه، وضعیت نامشخص ارسال را از شکست قطعی جدا کنید و امکان بررسی فهرست و تلاش مجدد را بدهید.
- تا مشخص‌شدن نتیجه ارسال، تصویر انتخاب‌شده را نگه دارید تا کاربر مجبور به عکاسی مجدد نشود.
