## محدوده و حفظ رفتار

- ۲۰ مصرف‌کننده، شامل API، Bridge و اعتبارسنج توکن، با نام کامل قرارداد بررسی و به سرویس جدید متصل شدند.
- Routeهای TrackingController، MeterReadingController و KartableAccessController به اتریبیوت کلاس منتقل شدند؛ URL، حروف مسیر، متد HTTP، مجوز و metadata اکشن‌ها حفظ شدند.
- تمام overloadهای ویرایش مشترک و مادر/فرزند حفظ شدند. TrackingFlowGetHandler تغییر نکرده است.
- متدهای کامل، field initializerها، سازنده‌ها، متن SQL و رشته‌های چندخطی با تصویر قبل از ادغام تطبیق داده می‌شوند. تبدیل CRLF/LF فقط در تطبیق Git HEAD با checkout ویندوز لحاظ می‌شود؛ در مقایسهٔ کد اجرایی قبل و بعد، متن literalها دقیق مقایسه می‌شود.
- نسخه‌های قبل در پروژهٔ تست نگهداری شده‌اند. namespace/importهای آزمایشی برای دسترسی به قراردادها و ثابت‌های داخلی تغییر کرده‌اند؛ بدنهٔ عملیات اصلی ثابت است.

## تست و بازبینی

- Build نهایی API و Bridge: هر دو بدون خطا.
- تست اختصاصی: ۲۵۶۸ بررسی موفق؛ ۴۳ امضای عمومی، ۱۲۳۷ سناریوی قبل/بعد و ۴۴۸ سناریوی خطا/تأخیر SQL. همهٔ مسیرهای ورودی با دادهٔ معتبر اجرا شدند؛ دو رفتار معیوب قبلی به‌صورت صریح در همین مقایسه‌ها ثبت شده‌اند.
- تطبیق ساختاری: ۱۰۰۷ بررسی؛ ۱۳۵ متد کامل، ۲۴ بدنهٔ تراکنش، ۸۶ متد مصرف‌کننده، ۱۹ نسخهٔ SQL و ۳ نسخهٔ command service برای bulk copy.
- پنج مجموعهٔ مستقل قبلی: ControllerConsolidation=۳۸۸۰، CriticalControllers=۱۶۳۹، Batch110=۲۴۲۴، Batch132=۱۰۷۹، Batch151=۵۵۲؛ همگی موفق.
- سه مرحلهٔ قبلی دوباره اجرا شدند: Critical10=۱۹۶۳، Auxiliary10=۱۶۰۱ و Management20=۲۰۷۹ بررسی رفتاری موفق؛ بررسی‌های ساختاری آن‌ها نیز به‌ترتیب ۶۹۸، ۴۹۰ و ۱۴۰۹ موفق بودند.
- مجموع بررسی‌های موفق این نوبت: ۲۱۳۸۹.
- بازبینی نهایی فهرست: ۱۰ از ۱۰ دسته و ۳۱ Handler/قرارداد حذف‌شده تطبیق داده شدند؛ هیچ ارجاع تولیدی به قراردادهای حذف‌شده باقی نمانده است.
- ثبت DI و عمر Scoped هر ۱۰ سرویس کنترل شده است.
- مقایسهٔ خروجی tuple برای این مرحله فعال است تا نتیجهٔ ورود و شناسه‌های ثبت درخواست هم بررسی شوند.
- کد ورود تصادفی، انقضای ۱۲۰ دقیقه، یکسان بودن شناسه و کد ذخیره‌شده با پاسخ، رد رمز/کد اشتباه و کاربر ناموجود کنترل می‌شوند.
- فایل بانکی دو ردیفی با مجموع ۳۵۰۰، مبلغ هر قسط، شناسه بانک و رد مبلغ/تعداد/بانک نادرست قبل از ذخیره بررسی می‌شود.
- فرمان‌های واقعی Dapper با connection ضبط‌کننده اجرا می‌شوند. خطای dependency و هر فرمان، لغو، await، open، begin، commit، disposal، isolation و اتصال فرمان به transaction مقایسه می‌شوند.
- برای SqlBulkCopy فقط مرز I/O در نسخهٔ آزمایشی جایگزین می‌شود. بدنهٔ واقعی ToDataTable، مقصد، options، ترتیب/نوع ستون‌ها، mapping و تمام ردیف‌ها ضبط می‌شوند؛ بدنهٔ سه command service با منبع تولیدی تطبیق داده می‌شود.
- ارتباط شناسه‌های Block → Tracking → Detail و شمارهٔ درخواست در پاسخ و تمام فرمان‌های SQL کنترل می‌شود.

## ایرادهای قبلی و محدودیت‌ها

در مسیر `CustomerMaintenance.UpdateAsync(MeterInstallationUpdateInputDto, ...)`، فراخوانی `transaction.Commit()` از قبل کامنت شده است. تست، اجرای فرمان‌ها و dispose بدون commit را در هر دو نسخه بازتولید می‌کند. این یک ایراد قبلی است که در ادغام اصلاح نشده؛ برابر بودن دو نسخه به معنی تأیید ثبت موفق این ویرایش در دیتابیس نیست.

در بررسی اولیهٔ ثبت درخواست خدمات پس از فروش (`RequestRegistration.CreateAfterSaleAsync`)، متد `SelectedServiceValidate(...)` بدون `await` فراخوانی می‌شد. پس از اصلاح دستی کاربر، فراخوانی helper نیز await شد. بررسی به‌روز در ۲۰۲۶/۱۱/۱۹ تأیید می‌کند تأخیر اعتبارسنجی مانع ادامهٔ عملیات است و خطا یا لغو آن جلوی Commit را می‌گیرد. snapshot اولیه حفظ شده و این اصلاح مشخص به‌صورت صریح در مقایسهٔ ساختاری اعمال می‌شود.

هیچ پیامک، job واقعی یا عملیات روی SQL Server واقعی اجرا نشده است. تست ضبط SqlBulkCopy، منطق تولید جدول و mapping را پوشش می‌دهد و جایگزین آزمون یکپارچهٔ provider روی دیتابیس آزمایشی نیست.

مجموعهٔ عمومی قدیمی MergedControllers همچنان mismatch شناخته‌شدهٔ fixture مسیر CollectBills/get دارد؛ تست اختصاصی این مرحله و مجموعه‌های مستقل جدا گزارش می‌شوند.

## بازبینی پس از گزارش توقف اجرا — ۲۰۲۶/۱۱/۱۹

وضعیت فایل‌ها و لاگ‌های ذخیره‌شده بررسی شد؛ ادغام هر ۱۰ دسته کامل بود و مورد ناتمامی در این مرحله پیدا نشد. بیلد API و Bridge دوباره بدون خطا انجام شد. تست اختصاصی با ۲۵۶۸ بررسی و تطبیق ساختاری با ۱۰۰۷ بررسی مجدداً پاس شدند؛ جمعاً ۳۵۷۵ بررسی در این بازاجرا موفق بود. فهرست ۳۱ Handler و قرارداد حذف‌شده، ۱۰ سرویس و ۲۰ مصرف‌کننده نیز دوباره کنترل شد؛ ارجاع قدیمی یا مسیر excel/sti/~ در دسته‌های انتخاب‌شده باقی نمانده است.

ایراد قبلیِ نبود Commit در ویرایش تاریخ نصب همچنان اصلاح نشده است. ایراد await اعتبارسنجی خدمات پس از فروش، پس از اصلاح دستی کاربر تکمیل و تست شد؛ تست به‌روز Workflow شامل ۲۵۵۶ کنترل، ۱۲۳۷ سناریوی مقایسه و ۴۴۸ حالت خطا/انتظار SQL است. هیچ اتصال واقعی به SQL Server، ارسال پیامک یا اجرای job انجام نشد.
