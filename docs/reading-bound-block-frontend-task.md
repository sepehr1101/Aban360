# تسک فرانت: مدیریت محدوده و بلوک قرائت

## هدف

کاربر بتواند محدوده‌های قرائت (`ReadingBound`) وابسته به منطقه و بلوک‌های زیرمجموعه (`ReadingBlock`) را مشاهده، ایجاد، ویرایش و حذف کند. رابط کاربری فارسی، راست‌به‌چپ و مطابق صفحات موجود پروژه باشد.

## ۱. مدیریت محدوده قرائت

- جدول شامل عنوان، عنوان منطقه، «از اشتراک»، «تا اشتراک» و عملیات باشد.
- عملیات هر ردیف: ویرایش، حذف و «مشاهده بلوک‌ها».
- فرم افزودن و ویرایش شامل عنوان، انتخاب منطقه، «از اشتراک» و «تا اشتراک» باشد.
- گزینه‌های منطقه از سرویس مناطق قابل دسترس کاربر دریافت شوند.
- اطلاعات فرم ویرایش از ردیف انتخاب‌شده در لیست تأمین شود.

## ۲. مدیریت بلوک قرائت

- با انتخاب محدوده یا کلیک روی «مشاهده بلوک‌ها»، فقط بلوک‌های همان محدوده نمایش داده شوند.
- جدول شامل عنوان بلوک، محدوده مرتبط، «از اشتراک»، «تا اشتراک» و عملیات ویرایش و حذف باشد.
- فرم افزودن و ویرایش شامل عنوان، محدوده مرتبط، «از اشتراک» و «تا اشتراک» باشد.
- محدوده انتخاب‌شده به‌صورت پیش‌فرض در فرم قرار گیرد.
- اطلاعات فرم ویرایش از ردیف انتخاب‌شده در لیست تأمین شود.
- با تغییر محدوده، لیست قبلی پاک و داده‌های محدوده جدید دریافت شوند.

## ۳. اتصال به API

مسیرها نسبت به آدرس پایه API هستند و درخواست‌ها به احراز هویت نیاز دارند.

| عملیات | متد | مسیر |
|---|---|---|
| لیست محدوده‌ها | GET | `/v1/reading-bound/all` |
| ایجاد محدوده | POST | `/v1/reading-bound/create` |
| ویرایش محدوده | POST | `/v1/reading-bound/update` |
| حذف محدوده | POST | `/v1/reading-bound/delete` |
| بلوک‌های یک محدوده | GET | `/v1/reading-block/all/{readingBoundId}` |
| ایجاد بلوک | POST | `/v1/reading-block/create` |
| ویرایش بلوک | POST | `/v1/reading-block/update` |
| حذف بلوک | POST | `/v1/reading-block/delete` |
| مناطق قابل دسترس کاربر | GET | `/v1/zone/all` |

**بدنه ایجاد محدوده:**

`{ title, zoneId, fromReadingNumber, toReadingNumber }`

`zoneTitle` ارسال نمی‌شود؛ عنوان منطقه فقط برای نمایش در جدول استفاده شود.

**بدنه ایجاد بلوک:**

`{ title, readingBoundId, fromReadingNumber, toReadingNumber }`

در ویرایش، `id` به بدنه ایجاد اضافه شود. بدنه حذف فقط `{ id }` است.

| عنوان نمایشی | نام فیلد API |
|---|---|
| از اشتراک | `fromReadingNumber` |
| تا اشتراک | `toReadingNumber` |

داده پاسخ داخل `data` قرار دارد. موفقیت و پیام‌ها مطابق ساختار استاندارد پاسخ پروژه خوانده شوند. پس از ایجاد موفق، لیست مجدداً دریافت شود.

## ۴. اعتبارسنجی و رفتار مشترک

- عنوان، انتخاب والد، «از اشتراک» و «تا اشتراک» الزامی باشند.
- مقادیر اشتراک به‌صورت رشته نگهداری و ارسال شوند تا صفرهای ابتدایی حفظ شوند.
- اعتبارسنجی ترتیب بازه، هم‌پوشانی و قرارگیری بلوک در بازه محدوده، مطابق قاعده کسب‌وکار مورد توافق انجام شود.
- حذف با تأیید کاربر انجام شود.
- هنگام ارسال درخواست، دکمه ثبت غیرفعال شود.
- حالت‌های بارگذاری، لیست خالی و خطا نمایش داده شوند.
- بعد از عملیات موفق، پیام موفقیت نمایش داده و لیست مربوطه تازه‌سازی شود.
- در خطا، فرم و اطلاعات واردشده حفظ و پیام سرویس نمایش داده شود.
- دسترسی عملیات مطابق سازوکار مجوزهای موجود پروژه اعمال شود.

## ۵. معیارهای پذیرش

- [ ] محدوده با منطقه صحیح ایجاد و ویرایش شود؛ `zoneTitle` در درخواست ایجاد ارسال نشود.
- [ ] بلوک با محدوده صحیح ایجاد و ویرایش شود.
- [ ] لیست بلوک‌ها فقط مربوط به محدوده انتخاب‌شده باشد.
- [ ] فرم ویرایش از داده لیست پر شود و نیازی به فراخوانی API جزئیات نباشد.
- [ ] عنوان‌های «از اشتراک» و «تا اشتراک» در تمام فرم‌ها و جدول‌ها استفاده شوند.
- [ ] حذف پس از تأیید انجام و نتیجه در لیست منعکس شود.
- [ ] صفرهای ابتدایی مقادیر اشتراک حفظ شوند.
- [ ] وضعیت‌های بارگذاری، خالی، موفقیت و خطا قابل مشاهده باشند.
