# دستور کار آماده برای Agent فرانت

متن زیر را همراه دسترسی به مخزن React و سند `FRONTEND_GUIDE.fa.md` به Agent بدهید.
مسیر مخزن React و تنظیمات محیط باید از پروژه واقعی خوانده شوند؛ این مخزن بک‌اند است.

---

قابلیت تیکتینگ Aban360 را داخل پروژه React موجود پیاده‌سازی کن.

ابتدا دستورالعمل‌های مخزن، ساختار featureها، مسیریابی، سیستم ورود، API client،
کامپوننت‌ها، RTL، فرم‌ها و روش مدیریت cache موجود را بررسی کن. از همان الگوها استفاده کن.
وابستگی یا سیستم ورود جدید اضافه نکن مگر نیاز آن از کد موجود روشن باشد.

سند `docs/ticketing/FRONTEND_GUIDE.fa.md` را کامل بخوان؛ قرارداد واقعی API،
قواعد دسترسی، نوع DTOها و معیار تحویل در آن آمده است. اگر این فایل کنار مخزن React
کپی شده، از همان نسخه استفاده کن. برای رفتار نامشخص به کد کنترلر، Handler و Validator
بک‌اند رجوع کن؛ endpoint، فیلد، نقش یا قابلیت جدید فرض نکن.

این صفحات را مطابق ساختار پروژه بساز: تیکت‌های من، ارجاع‌شده به من، مدیریت مدیر،
ثبت تیکت، گفتگو/پاسخ/پیوست/امتیاز، و گزارش. رابط فارسی، RTL، واکنش‌گرا و با حالت‌های
loading، empty، error و submitting باشد.

ابتدا مسیر کامل ثبت تیکت متنی تا پاسخ مسئول را قابل استفاده کن؛ سپس فایل‌ها، امتیاز،
مدیریت وضعیت/ارجاع و گزارش را تکمیل کن. از ابتدا قرارداد نهایی و typeهای واقعی را رعایت کن.
mock در صورت نیاز فقط مطابق همین قرارداد و با روش موجود پروژه باشد و مسیر محصول
در پایان به API واقعی متصل شود. آدرس سرور و کاربر جاری را از تنظیمات موجود بگیر.

نکته‌های الزامی:

1. تمام درخواست‌ها با احراز هویت موجود هستند؛ هویت ارسال‌کننده را در فرم نفرست.
2. پاسخ JSON دارای envelope و `data` است؛ فایل پاسخ باینری مستقل دارد.
3. create تیکت شماره پیگیری رشته‌ای می‌دهد؛ آن را شناسه عددی فرض نکن.
4. پیام اولیه همراه تیکت ساخته می‌شود؛ آن را دوباره ثبت نکن.
5. گفتگو، متادیتای پیوست و امتیاز با درخواست‌های جدا بارگیری می‌شوند؛ صفحه‌بندی را رعایت کن.
   برای صفحه «تیکت‌های من» از `POST /v1/ticket/my-list` استفاده کن؛ این مسیر برای مدیر
   هم فقط تیکت‌های خودش را می‌دهد و شناسه مالک از ورودی نمی‌گیرد.
6. فایل‌ها با FormData، حداکثر پنج فایل و هر فایل ۵۰ MiB ارسال می‌شوند؛ Content-Type
   multipart را دستی تعیین نکن. base64 JSON نفرست.
7. img/video با src مستقیم، هدر Bearer نمی‌فرستد؛ از دریافت Blob هنگام نیاز و مدیریت
   صحیح object URL استفاده کن. توکن را داخل URL نگذار و streaming احراز هویت‌شده را فرض نکن.
8. قواعد دسترسی و تیکت بسته را طبق سند اعمال کن؛ مدیر هم پیام دیگران را ویرایش نمی‌کند.
9. امتیاز به پاسخ متصل است، نه به کل تیکت؛ امتیاز موجود را با update ویرایش کن.
10. هنگام update تیکت، subject، assignedToUserId و statusId کامل فرستاده شوند؛
    PATCH هم قرارداد ویرایش جزئی ندارد.
11. میانگین null را «بدون امتیاز» نمایش بده؛ فیلتر تاریخ روی زمان ایجاد تیکت است.
12. متن پیام را escaped نمایش بده؛ هدر، تاریخ، خطا و nullها را مطابق سند پردازش کن.
13. ثبت‌ها را خودکار retry نکن؛ بعد از موفقیت، داده‌های مرتبط را تازه کن و فقط آن زمان فرم را پاک کن.
14. قابلیت حذف، اعلان، دسته‌بندی، اولویت یا API فرضی نساز.

تست‌های متناسب با ابزار موجود پروژه را اجرا کن و معیارهای تحویل انتهای راهنما را
بررسی کن. در پایان، صفحات ساخته‌شده، نتیجه بیلد/تست، تنظیمات لازم و محدودیت‌هایی
که به محیط یا بک‌اند وابسته‌اند گزارش کن. بدون تست واقعی، ادعای اتصال موفق به
SQL Server/FILESTREAM یا تأیید استقرار نکن.
