# بسته تحویل تیکتینگ به فرانت

بازبینی: ۲۰۲۶/۱۰/۲۷ — مخاطب: برنامه‌نویس یا AI Agent پروژه React موجود.

## از کجا شروع کنید؟

1. [راهنمای اصلی](FRONTEND_GUIDE.fa.md): جریان محصول، صفحات، داده‌ها، تمام عملیات،
   دسترسی‌ها، نمونه درخواست، فایل، خطا و معیار تحویل.
2. [دستور کار Agent](FRONTEND_AGENT_PROMPT.fa.md): متن آماده برای سپردن پیاده‌سازی به Agent.
3. [مرجع خلاصه مسیرها](../../Aban360.Api/Controllers/V1/UserPool/Ticketing/README.md):
   جدول همه ۲۱ مسیر API فعلی؛ دانلود و پیش‌نمایش دو حالت یک مسیر هستند.
4. [گزارش بازبینی](REVIEW.fa.md): اصلاحات و ریسک‌های باز سمت بک‌اند.

اگر مستندات را خارج از این مخزن می‌فرستید، کل پوشه `docs/ticketing` و فایل README
کنترلرهای تیکتینگ را همراه ساختار مسیرهای نسبی کپی کنید، یا مرجع API را جداگانه
ضمیمه کنید. صرفاً متن دستور کار Agent جای راهنمای اصلی را نمی‌گیرد.

## اطلاعات محیط که باید همراه مستند تحویل داده شوند

این اطلاعات را از محیط واقعی پروژه بگیرید؛ مقدار نمونه را در کد ثابت نگذارید:

- آدرس پایه API منتشرشده، شامل هر پیشوندی مثل virtual directory؛ مسیرهای سند نسبت به این پایه‌اند.
- آدرس Swagger در صورت فعال‌بودن؛ برای شروع، API client ورود فعلی پروژه هم کافی است.
- روش موجود دریافت/تمدید توکن و دسترسی به `userId` و وضعیت مدیر در فرانت.
- حساب تست مالک تیکت، حساب تست مسئول، و دسترسی مدیر برای ارجاع اولیه.
- شناسه GUID مسئول و روش lookup کاربران در پروژه موجود.
- آدرس مخزن/شاخه React، نحوه اجرای آن و تنظیمات اتصال API.

رمز و توکن واقعی را در مستند، مخزن یا prompt عمومی قرار ندهید؛ از روش خصوصی
تحویل دسترسی تیم استفاده کنید. آدرس و اطلاعات بالا در این مخزن برای محیط هاست
قطعی نشده‌اند و نباید توسط Agent حدس زده شوند.

## وضعیت آماده‌بودن بک‌اند

- APIها و Handlerهای تیکتینگ پیاده شده‌اند؛ «تیکت‌های من» مسیر مستقل دارد.
- طبق اعلام مالک پروژه، اسکریپت ساخت جداول روی سرور با موفقیت اجرا شده است.
- اجرای مایگریشن خودکار غیرفعال است؛ برای کار فرانت آن را فعال نکنید.
- تست‌های خودکار حافظه‌ای و HTTP اجرا شده‌اند؛ اتصال کامل به محیط منتشرشده باید
  با سناریوی زیر تأیید شود. این سند ادعای تست موفق روی هاست را نمی‌کند.

## تست اولیه اتصال، قبل از ساخت همه صفحات

از Swagger یا ابزار HTTP موجود تیم استفاده کنید. تمام درخواست‌ها احراز هویت می‌خواهند.
شناسه‌های زیر باید از پاسخ واقعی مرحله قبل استخراج شوند؛ عدد نمونه را حدس نزنید.

| مرحله | هویت | درخواست | نتیجه مورد انتظار |
|---|---|---|---|
| ۱ | مالک | `GET /v1/ticket-status/list` | HTTP 200، چهار وضعیت داخل `data` |
| ۲ | مالک | `POST /v1/ticket/create` با multipart `Subject`، `Body` و یک عکس کوچک در `Attachments` | شماره پیگیری رشته‌ای داخل `data` |
| ۳ | مالک | `POST /v1/ticket/my-list` با `{}` | تیکت ساخته‌شده؛ شناسه عددی را با تطبیق دقیق شماره پیگیری پیدا کنید |
| ۴ | مدیر | `POST /v1/ticket/update` با `id`، `subject`، GUID واقعی مسئول و `statusId: 2` | `data: true` |
| ۵ | مسئول | `POST /v1/ticket-message/create` با multipart `TicketId` و `Body` | `data: true`؛ تیکت پاسخ‌داده‌شده می‌شود |
| ۶ | مالک | `POST /v1/ticket-message/list` با `{ "ticketId": شناسه_واقعی }` | پیام اولیه و پاسخ؛ شناسه هر دو را استخراج کنید |
| ۷ | مالک | `GET /v1/ticket-attachment/list/{messageId}` برای پیام اولیه، سپس `GET /v1/ticket-attachment/content/{id}?download=true` | متادیتا و فایل قابل بازشدن؛ با فیلم کوچک هم تکرار کنید |
| ۸ | مالک | `POST /v1/ticket-rating/create` با شناسه پاسخ مسئول و `score: 5` | `data: true` |
| ۹ | مالک | `POST /v1/ticket/report` با `{}` | شمارنده و میانگین؛ اگر فقط همین داده تست موجود است: تعداد ۱، امتیاز ۱، میانگین ۵ |
| ۱۰ | کاربر نامرتبط | خواندن همان تیکت یا فایل | محتوای خصوصی دریافت نشود؛ خطای دامنه فعلی ممکن است HTTP 400 باشد |

ردیف ۶، نمایش خلاصه ورودی است؛ در JSON واقعی، مقدار `ticketId` باید عدد باشد.
برای تکرار آزمایش، داده‌های قبلی را در شمارنده گزارش لحاظ کنید؛ API حذف نداریم.
اگر مرحله‌ای شکست خورد، مسیر، روش HTTP، زمان، status و پاسخ خطا را بدون توکن
برای تیم بک‌اند ثبت کنید. پیش از رفع مشکل اتصال، پاسخ‌های فرضی جایگزین API واقعی نکنید.

## پنج نکته‌ای که نباید در فرانت اشتباه شوند

- «تیکت‌های من»: `POST /v1/ticket/my-list`، بدون ورودی مالک؛ حتی مدیر فقط تیکت خودش را می‌گیرد.
- پیام اولیه در create تیکت ساخته می‌شود؛ آن را دوباره با create پیام ارسال نکنید.
- JSON دارای envelope است؛ محتوای فایل باینری است و نباید JSON parse شود.
- برای فایل با JWT، تگ img/video مستقیم هدر Bearer نمی‌فرستد؛ روش Blob و آزادسازی URL در راهنما آمده است.
- update تیکت، حتی با PATCH، ورودی کامل می‌خواهد؛ مسئول را ناخواسته null نکنید.

کار را با فهرست، ثبت تیکت و پاسخ متنی شروع کنید، سپس پیوست، امتیاز، مدیریت و گزارش
را تکمیل کنید. طراحی، ابزارها، استایل و مسیریابی باید ادامه همان پروژه React موجود باشد.
