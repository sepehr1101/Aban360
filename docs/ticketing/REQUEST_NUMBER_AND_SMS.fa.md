# تغییرات تیکتینگ برای برنامه‌نویس فرانت

این راهنما فقط تفاوت با API قبلی را توضیح می‌دهد؛ برای اعمال این تغییرات، نیازی به خواندن دوبارهٔ مستندات کامل نیست.

## مقایسهٔ قبل و بعد

| مورد | قبل | بعد / اقدام لازم در فرانت |
|---|---|---|
| خروجی ثبت `POST /v1/ticket/create` | مقدار `data` یک رشتهٔ `ticketNumber` بود. | مقدار `data` یک شیء شامل `id`، `ticketNumber` و `requestNumber` است؛ نوع خروجی کلاینت را تغییر دهید. |
| شمارهٔ قابل نمایش | فیلد خوانای جداگانه وجود نداشت. | `requestNumber` مانند `"00000125"` را با عنوان «شماره درخواست» در فهرست و جزئیات پنل کاربر و ادمین نمایش دهید. |
| رفتن به جزئیات پس از ثبت | با `ticketNumber` در فهرست جستجو می‌شد تا `id` پیدا شود. | مستقیماً از `data.id` پاسخ ثبت استفاده کنید؛ جستجوی اضافه را حذف کنید. |
| پیام موفقیت ثبت | شمارهٔ نمایشی در پاسخ ثبت موجود نبود. | دقیقاً پیام «تیکت شما با شماره ... با موفقیت ثبت گردید» را با مقدار `data.requestNumber` نمایش دهید. |
| مدل جزئیات و فهرست‌ها | شامل `id` و `ticketNumber` بود. | فیلد `requestNumber: string` اضافه شده است؛ سایر فیلدها برقرارند. |
| ارسال پیامک | اعلان‌های جدید ثبت و پاسخ وجود نداشتند. | بک‌اند به ایجادکنندهٔ تیکت پیامک می‌فرستد؛ فرانت اقدام یا فراخوانی جداگانه‌ای ندارد. |

## تغییر پاسخ ثبت

قبل، مقدار `data`:

```json
"شناسهٔ فعلی تیکت"
```

بعد، مقدار `data`:

```json
{
  "id": 125,
  "ticketNumber": "شناسهٔ فعلی تیکت",
  "requestNumber": "00000125"
}
```

قالب عمومی پاسخ API حفظ شده است؛ فقط نوع `data` در پاسخ ثبت از رشته به شیء تغییر کرده است. شمارهٔ درخواست در بدنهٔ پاسخ است و هیچ هدر سفارشی برای آن وجود ندارد. توضیح قبلی دربارهٔ خواندن شماره از هدر را کنار بگذارید.

## تغییر کد کلاینت

قبل، با فرض اینکه `ticketingRequest` مقدار `data` را برمی‌گرداند:

```ts
const ticketNumber = await ticketingRequest<string>("/v1/ticket/create", "POST", form);
// جستجوی فهرست با ticketNumber برای یافتن id
```

بعد:

```ts
interface TicketCreateResult {
  id: number;
  ticketNumber: string;
  requestNumber: string;
}

const result = await ticketingRequest<TicketCreateResult>(
  "/v1/ticket/create", "POST", form
);
const successMessage = `تیکت شما با شماره ${result.requestNumber} با موفقیت ثبت گردید`;
// پیام را با سازوکار فعلی نمایش پیام موفقیت نشان دهید.
// برای رفتن به جزئیات، از result.id استفاده کنید.
```

نمونهٔ متن قابل نمایش پس از موفقیت API:

> تیکت شما با شماره 00000125 با موفقیت ثبت گردید

پیام فقط پس از تأیید موفقیت API نمایش داده شود. `requestNumber` را رشته نگه دارید تا صفرهای ابتدایی حذف نشوند. این شماره برای تیکت‌های قبلی نیز در خروجی موجود است.

## مواردی که تغییر نکرده‌اند

مسیرها، ورودی `multipart/form-data` ثبت، فایل‌ها، احراز هویت و عملیات پاسخ و ویرایش تغییری نکرده‌اند. برای همهٔ عملیات همچنان از `id` استفاده کنید؛ `requestNumber` فقط برای نمایش است و جایگزین شناسهٔ عملیاتی یا `ticketNumber` نمی‌شود. تغییر دیتابیس و اجرای SQL لازم نیست.
