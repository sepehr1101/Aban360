# ادغام دسته‌های ۱۱ تا ۲۰

۳۸ Handler و قراردادهای متناظر آن‌ها در ۱۰ سرویس تجمیع شدند. تعداد کلاس‌های پیاده‌سازی این بخش در کد اجرایی ۲۸ مورد کمتر شد.

| دسته | سرویس نهایی | Handler قبلی |
|---|---|---:|
| MeterApkLog | MeterApkLogService | ۳ |
| AssessmentLog | AssessmentLogService | ۳ |
| ServerInfo | ServerInfoService | ۲ |
| UserSearch | UserSearchService | ۳ |
| Document | DocumentService | ۷ |
| MeterApkFile | MeterApkFileService | ۸ |
| SmsStateTemplate | SmsStateTemplateService | ۴ |
| SmsFlow | SmsFlowService | ۴ |
| SmsType | SmsTypeApplicationService | ۲ |
| SmsStateGroup | SmsStateGroupApplicationService | ۲ |

نام دو سرویس آخر برای جلوگیری از تداخل با سرویس‌های موجود Persistence، پسوند `ApplicationService` دارد. قرارداد و پیاده‌سازی هر سرویس در یک فایل کنار هم قرار دارند.

## دامنهٔ تغییر

۱۶ مصرف‌کننده به سرویس‌های جدید متصل شدند: ۱۴ کنترلر و دو کلاس Gateway مربوط به سند. کلاس‌های ارسال پیامک، زمان‌بند ارسال، موتور محاسبهٔ قبض، فایل‌های SQL و CommandServiceهای Persistence تغییر نکرده‌اند. Route، HTTP verb، ورودی، خروجی، شناسهٔ مجوز و ترتیب فراخوانی‌ها حفظ شده‌اند.

کلاس‌های قبل از ادغام و قراردادهای قدیمی فقط در تست‌ها نگه داشته شده‌اند تا بدنهٔ عملیات و رفتار نسخهٔ قبل و بعد قابل مقایسه باشد.

## بررسی‌های اختصاصی

| بررسی | نتیجه |
|---|---|
| Build نهایی API و Bridge | موفق، بدون خطای کامپایل؛ هشدارهای موجود پروژه باقی‌اند |
| مقایسهٔ ساختاری با منابع Git | ۴۹۰ بررسی موفق؛ ۵۴ متد سرویس، ۴۳ متد مصرف‌کننده و ۹ مسیر عملیات دارای تراکنش |
| بررسی سرویس‌ها | ۳۰۵ بررسی؛ ۱۰ ثبت DI و lifetime از نوع Scoped، ۳۸ عملیات، ۱۷۳ سناریوی قبل/بعد |
| بررسی SQL با Dapper واقعی و اتصال ثبت‌کننده | ۱۰۳۸ بررسی؛ ۹ عملیات و ۱۳۴ سناریوی قبل/بعد |
| بررسی مجدد ثبت‌کنندهٔ مشترک با MainTagGroup | ۲۵۸ بررسی موفق |
| مجموع بررسی‌های رفتاری این اجرا | ۱۶۰۱ بررسی |
| بازاجرای تست‌های رفتاری مرحلهٔ اول | ۱۹۶۳ بررسی موفق |
| بازاجرای تحلیل ساختاری مرحلهٔ اول با Git | ۶۹۸ بررسی موفق |
| پنج مجموعهٔ رگرسیون قبلی | ۹۵۷۸ بررسی موفق |

تست تراکنش از نسخه‌های مخصوص تستِ کد قبل و بعد استفاده می‌کند که تنها namespace و کلاس پایهٔ اتصال آن‌ها عوض شده است. تحلیل ساختاری، یکسان بودن اعضای این ۱۴ نسخه با منابع متناظر را بررسی می‌کند. CommandServiceهای واقعی Dapper اجرا می‌شوند، اما فرمان‌ها و پارامترها در حافظه ثبت می‌شوند.

در مسیرهای پیامک، مقادیر مشخص `GroupId`، `SmsTypeId`، `StepOrder`، `DueDay`، `SmsText`، `FirstFlowId`، `SmsCount`، `SmsTemplateId`، تاریخ تبدیل‌شدهٔ اجرا و شناسهٔ ایجادکننده کنترل شدند. خطای اعتبارسنجی، تعریف تکراری، تاریخ نامعتبر، خطای فرمان، مقدار برگشتی نامعتبر، لغو، تأخیر Task و رفتار Commit نیز پوشش داده شدند.

تست‌های لاگ فقط در پوشهٔ موقتِ اختصاصی اجرا شدند و بایت‌های فایل ذخیره‌شده بررسی شدند. عملیات سند با فایل حافظه‌ای تست شد. زمان جاری و شناسه‌های تصادفیِ تولیدشده، پس از کنترل معتبر بودن، برای مقایسهٔ دو اجرا نرمال می‌شوند. اطلاعات زندهٔ زمان سیستم و فضای آزاد دیسک نیز جدا از اطلاعات ثابت مقایسه می‌شوند.

## ایرادهای موجود پیش از ادغام

- نگاشت AutoMapper از `DocumentUpdateDto` به `Document` در پروفایل موجود تعریف نشده است. اجرای ویرایش سند در هر دو نسخه، قبل و بعد از ادغام، همان خطا را تولید می‌کند. این مورد در تست صریحاً به‌عنوان شکست مورد انتظار مقایسه می‌شود و عملیات موفق شمرده نمی‌شود. منطق آن اصلاح نشده است.
- مسیرهای تغییر فایل APK از دو اتصال و دو تراکنش مستقل استفاده می‌کنند و Commit آن‌ها متوالی است. تست، رفتار خطا در هر Commit و وضعیت آزادسازی منابع را بین دو نسخه مقایسه می‌کند؛ این ادغام atomic بودن دو تراکنش را تغییر نمی‌دهد.
- ناسازگاری قبلی فایل انتظار تست‌های عمومی با اکشن‌های جداشدهٔ GET و POST در `CollectBills` خارج از این مرحله است و تغییر نکرده است.

هیچ پیامک واقعی، اتصال به دیتابیس واقعی یا Job پس‌زمینه‌ای اجرا نشده است. تست یکپارچه با SQL Server واقعی یا سرویس پیامک واقعی انجام نشده است.

پنج مجموعهٔ رگرسیون نهایی شامل `ControllerConsolidation` با ۳۸۸۴ بررسی، `CriticalControllers` با ۱۶۳۹ بررسی، `ControllerBatch110` با ۲۴۲۴ بررسی، `ControllerBatch132` با ۱۰۷۹ بررسی و `ControllerBatch151` با ۵۵۲ بررسی هستند. کاهش دو بررسی در مجموعهٔ اول نسبت به مرحلهٔ قبل مربوط به کاهش تعداد وابستگی‌های سازنده است؛ تعداد ۴۵۰ اکشن و ۸۰۸ ترکیب HTTP/Route آن مجموعه ثابت است.

## اجرای مجدد

```powershell
dotnet build Aban360.Api/Aban360.Api.csproj --no-restore -m:1
dotnet build Aban360.BrdigeApi/Aban360.BrdigeApi.csproj --no-restore -m:1
dotnet build tests/Aban360.MergedControllers.SmokeTests --no-restore -m:1 -p:BuildProjectReferences=false
dotnet run --project tests/Aban360.MergedControllers.SmokeTests --no-build --no-restore --no-launch-profile -- --auxiliary10
dotnet run --project tests/Aban360.CriticalServiceStructure.RegressionTests -- --auxiliary10
```

پروژهٔ تحلیل ساختاری به SDK دات‌نت ۱۰ نیاز دارد. پروژه‌های اصلی و تست رفتاری همچنان هدف دات‌نت ۸ دارند. گزینهٔ اختیاری `--verify-head` برای مقایسهٔ نسخه‌های ثابت با Git HEAD قبل از commit ادغام قابل استفاده است.
