# راهنمای فرانت برای فهرست فایل‌های بایگانی (directory-tree2)

این APIها فهرست فایل‌ها را همراه عنوان نمایشی هر فایل برمی‌گردانند. برای نمایش فهرست، درخواست جداگانه `file-title` لازم نیست؛ محتوای هر تصویر با یک درخواست جداگانه دریافت می‌شود.

در تمام مسیرهای فهرست، هدر زیر ارسال شود:

```http
Authorization: Bearer {accessToken}
```

`{apiBaseUrl}` آدرس پایه API در تنظیمات فعلی برنامه است. مقادیر پارامترهای آدرس را URL-encode کنید.

## ۱. انتخاب مسیر فهرست

پیشوند تمام مسیرهای جدول `{apiBaseUrl}/v1/open-km/` است:

| کاربرد | روش | مسیر | ورودی |
| --- | --- | --- | --- |
| بایگانی قبض | GET | `directory-tree2` | `input`: شناسه قبض؛ `trackNumber`: شماره پیگیری اختیاری |
| بایگانی تخفیف | GET | `discount-directory-tree2` | `input`: همان شناسه بایگانی تخفیف که در صفحه فعلی ارسال می‌شود |
| بایگانی درخواست | GET | `request-directory-tree2` | `input`: شماره پیگیری بدون پیشوند `r_` |
| فایل‌های حذف‌شده | POST | `removed-directory-tree2` | بدنه JSON مطابق بخش بعد |
| تصاویر قرائت کنتور | GET | `reading-directory-tree2` | `billId`: شناسه قبض |

### بایگانی قبض

```http
GET {apiBaseUrl}/v1/open-km/directory-tree2?input={billId}
```

اگر شماره پیگیری مربوط به همان قبض نیز در دسترس است:

```http
GET {apiBaseUrl}/v1/open-km/directory-tree2?input={billId}&trackNumber={trackNumber}
```

برای انشعاب تازه ثبت‌شده، ارسال شماره پیگیری مربوط به همان انشعاب ممکن است برای دریافت بایگانی لازم باشد. مقدار ناموجود را به‌صورت رشته `null` ارسال نکنید؛ پارامتر اختیاری را حذف کنید.

### بایگانی تخفیف

```http
GET {apiBaseUrl}/v1/open-km/discount-directory-tree2?input={discountArchiveId}
```

مقدار `input` در مهاجرت از `discount-directory-tree` تغییری نمی‌کند.

### بایگانی درخواست

```http
GET {apiBaseUrl}/v1/open-km/request-directory-tree2?input={trackNumber}
```

شماره پیگیری را خام ارسال کنید؛ پیشوند `r_` اضافه نکنید.

### فایل‌های حذف‌شده

```http
POST {apiBaseUrl}/v1/open-km/removed-directory-tree2
Content-Type: application/json
```

برای فایل‌های حذف‌شده یک قبض:

```json
{
  "folderName": "شناسه قبض",
  "isBillId": true
}
```

برای فایل‌های حذف‌شده یک درخواست:

```json
{
  "folderName": "شماره پیگیری بدون پیشوند",
  "isBillId": false
}
```

این درخواست فقط فهرست فایل‌های حذف‌شده را می‌خواند و فایلی را حذف نمی‌کند.

### تصاویر قرائت کنتور

```http
GET {apiBaseUrl}/v1/open-km/reading-directory-tree2?billId={billId}
```

این مسیر فقط تصاویر قرائت همان قبض را برمی‌گرداند. برای ارسال عکس از اپلیکیشن اندروید و شرایط پذیرش تصویر، [راهنمای تصاویر قرائت](reading-images-api.fa.md) را ببینید.

## ۲. خواندن پاسخ فهرست

آرایه فایل‌ها در همه مسیرها `data.document` است. نمونه زیر بخش‌های کاربردی پاسخ را نشان می‌دهد؛ ممکن است فیلدهای دیگری نیز وجود داشته باشند:

```json
{
  "success": true,
  "httpStatusCode": 200,
  "data": {
    "document": [
      {
        "uuid": "document-uuid",
        "title": "scan.jpg",
        "mimeType": "image/jpeg",
        "fileTitle": "سند مالکیت"
      }
    ]
  }
}
```

| فیلد هر فایل | کاربرد در فرانت |
| --- | --- |
| `uuid` | شناسه فایل برای دریافت محتوا |
| `fileTitle` | عنوان نمایشی فایل |
| `title` | نام یا عنوان فایل؛ جایگزین نمایشی در صورت خالی‌بودن `fileTitle` |
| `mimeType` | تشخیص نوع فایل و انتخاب نحوه نمایش یا آیکون |
| `created` | تاریخ ثبت سند |
| `actualVersion.size` | اندازه فایل |

عنوان را به این ترتیب انتخاب کنید: `fileTitle` غیرخالی، سپس `title` و در نبود هر دو، «فایل بدون عنوان». خالی‌بودن عنوان نباید باعث حذف فایل از نمایش یا غیرفعال‌شدن دریافت آن شود.

در فهرست تصاویر قرائت، مقدار `fileTitle` برابر «تصویر قرائت کنتور» است.

## ۳. دریافت تصویر یا محتوای فایل

فهرست، محتوای فایل را برنمی‌گرداند. برای هر فایل موردنیاز از `uuid` استفاده کنید:

```http
GET {apiBaseUrl}/v1/open-km/document-binary?documentId={uuid}&isThumbnail=false
```

دریافت و نمایش محتوای پاسخ مطابق قرارداد فعلی `document-binary` انجام می‌شود. برای نسخه اصلی، `isThumbnail=false` ارسال کنید. مسیر یا نام فایل را جایگزین `uuid` نکنید.

فایل‌های غیرتصویری را با توجه به `mimeType` نمایش دهید یا امکان بازکردن و دریافت آن‌ها را فراهم کنید. برای فهرست‌های طولانی، محتوای تصاویر را هنگام نیاز به نمایش دریافت کنید و از دریافت دوباره محتوای یک `uuid` بدون نیاز جلوگیری کنید.

## ۴. تغییرات لازم برای مهاجرت صفحات فعلی

1. مسیر فهرست هر صفحه را طبق جدول زیر تغییر دهید؛ ورودی‌های همان صفحه حفظ می‌شوند.
2. فهرست را از `data.document` بخوانید.
3. عنوان نمایشی را از `fileTitle` بخوانید و درخواست جداگانه `file-title` برای تک‌تک فایل‌ها را حذف کنید.
4. دریافت محتوا با `document-binary` و `uuid` مانند قبل ادامه دارد.

| مسیر فعلی | مسیر جدید |
| --- | --- |
| `directory-tree` | `directory-tree2` |
| `discount-directory-tree` | `discount-directory-tree2` |
| `request-directory-tree` | `request-directory-tree2` |
| `removed-directory-tree` | `removed-directory-tree2` |

برای مثال، نمایش ۸ تصویر به یک درخواست فهرست و ۸ درخواست دریافت محتوا نیاز دارد؛ ۸ درخواست جداگانه عنوان حذف می‌شوند.

## ۵. وضعیت‌های صفحه و خطاها

- هنگام دریافت فهرست، وضعیت بارگذاری نمایش دهید.
- پس از پاسخ موفق، اگر `data.document` خالی بود، پیام «فایلی برای نمایش وجود ندارد» نمایش دهید.
- اگر دریافت فهرست ناموفق بود، پیام خطای API را از `errors[].message` نمایش دهید و امکان تلاش مجدد بدهید؛ خطا را به‌صورت فهرست خالی نشان ندهید.
- خطای دریافت یک تصویر را در همان آیتم با امکان تلاش مجدد نمایش دهید؛ سایر فایل‌ها قابل نمایش بمانند.
- اگر کاربر در زمان بارگذاری، قبض یا شماره پیگیری را تغییر داد، نتیجه درخواست قبلی را روی فهرست انتخاب جدید نمایش ندهید.
- در پایان اعتبار ورود، مطابق روال ورود فعلی برنامه عمل کنید.
