# اجرای دستی PaymentPool روی Atlas

1. در SSMS به **سرور مقصد** متصل شوید و دیتابیس موجود **Atlas** را به عنوان دیتابیس جاری انتخاب کنید.
2. فایل `001_PaymentPool_Base_Atlas.sql` را اجرا کنید؛ ساختار پایه و داده‌های مرجع ضروری PaymentPool را در صورت نبودن ایجاد می‌کند.
3. فایل `002_BankReceipt_Atlas.sql` را اجرا کنید؛ جدول‌های ورود فایل، مغایرت، حذف منطقی، شاخص‌ها و trigger شرح غیرقابل‌تغییر را ایجاد یا تکمیل می‌کند.
4. اتصال نرم‌افزار را با کلید `ConnectionStrings:PaymentPoolConnection` تنظیم کنید و سپس برنامه را اجرا کنید.

هر دو اسکریپت نام دیتابیس جاری را بررسی می‌کنند و اگر Atlas نباشد متوقف می‌شوند. روی همان سروری اجرا می‌شوند که در SSMS به آن متصل هستید؛ نام سرور مقصد داخل اسکریپت تعبیه نشده است. دیتابیس جدید ساخته نمی‌شود. خطاهای اجرا باعث rollback همان فایل می‌شوند. اسکریپت‌ها داده‌های موجود را حذف نمی‌کنند و برای اجرای مجدد طراحی شده‌اند؛ سازگاری کامل با ساختارهای سفارشی موجود روی Atlas باید هنگام اجرای دستی بررسی شود. نیاز به SQL Server 2016 SP1 یا جدیدتر و compatibility level حداقل 130 وجود دارد.

## تنظیم اتصال نرم‌افزار

در appsettings، حالت زیر فعال شده است:
```json
"PaymentPool": { "ManualMigrations": true }
```

رشته اتصال واقعی را در تنظیمات محیط اجرا، User Secrets یا متغیر محیطی `ConnectionStrings__PaymentPoolConnection` قرار دهید. نمونه ساختار برای احراز هویت ویندوز:
```text
Server=<ATLAS_SERVER>;Database=Atlas;Integrated Security=True;Encrypt=True;TrustServerCertificate=False;
```

در صورت استفاده از SQL Authentication، نام کاربری و رمز را مطابق تنظیمات سرور خود وارد کنید. مقادیر اتصال و رمز واقعی در این تغییر ثبت نشده‌اند.

وقتی ManualMigrations فعال باشد، هم migrationها و هم seedهای PaymentPool از مسیر خودکار DefaultConnection کنار گذاشته می‌شوند. اتصال EF و Dapper این ماژول از PaymentPoolConnection خوانده می‌شود. سایر ماژول‌ها همچنان DefaultConnection را به کار می‌برند. برنامه تا زمانی که PaymentPoolConnection تنظیم نشود یا اگر Database آن Atlas نباشد، با پیام روشن متوقف می‌شود و به صورت خودکار به Aban360 برنمی‌گردد.

فایل قدیمی `DbSeeder/DataScript/Bank.sql` حاوی USE Aban360 است؛ برای راه‌اندازی Atlas آن را اجرا نکنید. اطلاعات لازم بانک‌ها در اسکریپت 001 موجود است. اسکریپت‌های دستی سوابق FluentMigrator عمومی را تغییر نمی‌دهند؛ ثبت اجرای دستی در PaymentPool.ManualSchemaVersion نگهداری می‌شود. پس از استقرار دستی، ManualMigrations را فعال نگه دارید.

این اسکریپت‌ها **انتقال داده بین دو سرور** انجام نمی‌دهند. اگر PaymentPool قبلاً در Aban360 داده واقعی دارد، انتقال آن داده‌ها و حفظ شناسه‌ها و روابط باید جداگانه انجام شود؛ قبل از ایجاد داده‌های مرجع جدید در Atlas، وضعیت داده‌های مقصد و شناسه‌های بانک‌ها را بررسی کنید. حساب‌های واقعی بانکی و نمونه‌های آزمایشی Uploader از seeder قدیمی کپی نشده‌اند.

این تغییر هیچ اسکریپتی را روی Atlas یا Aban360 اجرا نکرده است. فایل‌های SQL برای اجرا توسط شما آماده‌اند و روی SQL Server واقعی آزمایش نشده‌اند.
